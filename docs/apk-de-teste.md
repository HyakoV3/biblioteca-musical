# APK de teste fechado (com conteúdo embutido)

Para dar a outros músicos algo para testar, o build pode levar um `hinario.json` **dentro do binário**. O
conteúdo **nunca entra no Git**: só o caminho do arquivo é informado na hora do build.

> **Direitos.** O conteúdo são transcrições de terceiros, ainda sem autorização (ver `docs/roadmap-uxui-inicial.md`,
> seção 3). Use só em **teste fechado**. **Não publique** o APK (loja, redes, link aberto) antes da autorização.

## Como funciona

- `src-tauri/build.rs` lê a variável `BM_PACOTE` (caminho de um `hinario.json`) e a copia para dentro do binário.
  Sem a variável, o app não leva conteúdo nenhum além do pacote de exemplo fictício.
- Na primeira abertura, o app grava esse conteúdo como se a pessoa o tivesse instalado (`hinario::semear`).
  Ela pode removê-lo em **Ajustes**. **Desde o 060 os APKs de teste saem SEM o hinário embutido** (sem `BM_PACOTE`): o hinário é
  baixado pelo app, de uma pasta própria do servidor ([`pacote-do-hinario.md`](pacote-do-hinario.md)).
- Uma versão nova do APK com **conteúdo diferente** o substitui. Quem importou um hinário próprio **antes** de existir
  conteúdo embutido não perde o seu (só é sobrescrito por uma atualização posterior com conteúdo novo).

## Depois de cada merge: a verificação dos pacotes

Toda vez que código novo entra na `main` (a PR foi mergeada no GitHub, ou o responsável avançou a `main` local para testar), o
assistente roda esta verificação **antes de dizer que terminou**. A pergunta é: **o que mudou desde o último APK entregue e,
portanto, quais pacotes precisam ser refeitos?** Ela vale também para o merge local de um ramo de teste, porque o hinário do
emulador pode ficar velho mesmo sem PR (foi o que aconteceu com os `compassos`).

1. **Atualizar.** `git fetch`; o worktree do assistente vai para `origin/main` (`git switch --detach origin/main`); os ramos locais
   já mergeados saem (`git branch -d`, que recusa o que não foi mergeado). A `main` **local do responsável** o assistente não
   alcança (a sessão isolada não mexe na pasta principal): **dá o comando** para o terminal comum dele
   (`cd <pasta do projeto> && git pull --ff-only`, ou `git merge --ff-only <ramo>` num teste local).
2. **O que mudou desde o último APK.** `git diff --stat <commit do último APK, da tabela abaixo> origin/main -- <caminhos>`:

   | Mudou | Refazer |
   |---|---|
   | `src/`, `static/`, `package.json` (o front) | **APK** novo |
   | `src-tauri/` (o Rust, o manifesto do Android, os ícones) | **APK** novo |
   | `tools/mscx2json/` ou o formato do hinário (`docs/FORMATO.md`, `src-tauri/src/hinario.rs`) | o **hinário** `.json`: o embutido no APK e o do emulador (passo 4) |
   | `tools/gerar-partituras.py`, `tools/montar-pacote.py`, a limpeza do SVG ou o formato do pacote | **pacote de partituras** novo (`partituras-<sha8>.zip`): subir ao servidor e atualizar `src/lib/partituras/manifesto.json` (o que muda o front, então também o **APK**) |
   | `src/lib/sons/manifesto.json` ou o pacote de sons | o **zip dos sons** |
   | só `docs/`, `tests/`, `.github/` | **nada**: nenhum pacote |

3. **Conferir o que não mudou, em vez de supor.** O SHA-256 do `partituras-00N.zip` **no servidor** (`ssh <servidor> sha256sum …`,
   só leitura) tem de ser o do `manifesto.json` do app; o hinário regenerado tem de ser **idêntico** ao anterior e ao do
   Download do emulador (`sha256sum`). Se bate, o pacote **não** é refeito, e a resposta diz isso.
4. **O hinário do emulador** (só se o conversor ou o formato mudou). Gerar com o **mesmo `id`, nome e idioma do instalado**
   (hoje `amostra`, "Amostra local (não publicar)", `pt-BR`; com outro `id` as partituras já baixadas são apagadas pela marca
   `.hinario`) e com `--correcoes`; `adb push` para `/sdcard/Download/` e uma cópia em `content/amostras/`. O responsável
   **reimporta pela tela**: o assistente não toca na tela nem importa por conta própria. Conferir com `run-as` (só leitura) o
   que o app instalado tem. Se o JSON é idêntico ao que já está lá, **não há nada a jogar**: só se diz isso.
5. **O APK** (se o front ou o Rust mudaram). Árvore **limpa** (senão o rótulo de versão sai com "+"), compilar, assinar,
   **conferir o conteúdo** (o hinário embutido com os `compassos`; o front com o commit certo), entregar no zip numerado e
   **registrar a linha** na tabela abaixo, numa PR de docs.
6. **Dizer o que foi refeito e o que não foi, com o motivo**, na linha da tabela e na resposta ao responsável.

## Gerar

```sh
export JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64          # o Java padrão (25) pode não servir ao Gradle
export ANDROID_HOME=~/Android/Sdk ANDROID_SDK_ROOT=~/Android/Sdk
export NDK_HOME=~/Android/Sdk/ndk/30.0.16248370
npm run tauri android build -- --apk --target aarch64                      # sem hinário embutido (o padrão desde o 060)
# BM_PACOTE=/caminho/do/hinario.json npm run tauri android build -- --apk --target aarch64   # só se for embutir um hinário
```

Sai `src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release-unsigned.apk` (~5 MB sem o hinário; ~6 MB com ele).
**Conferir o tamanho:** bem acima disso, o APK está levando algo velho. Se o **nome da biblioteca Rust mudar** (o `name` do `[lib]` do `src-tauri/Cargo.toml`), apague as `lib*.so` antigas
de `src-tauri/gen/android/app/src/main/jniLibs/*/` antes de gerar: elas ficam lá (pasta gerada, fora do Git) e entram no APK sem uso (foi o que aconteceu do 062 ao 064, +3,8 MB).
**Não use `--debug`**: o APK fica com ~270 MB.

`--target aarch64` gera só para `arm64` (quase todos os celulares atuais; aparelhos de 32 bits não instalam).

## Assinar (obrigatório para instalar)

O Android não instala APK sem assinatura. Para **teste fechado**, assine com a chave de depuração que o Android
Studio cria em `~/.android/debug.keystore` (senha padrão `android`, alias `androiddebugkey`):

```sh
BT=~/Android/Sdk/build-tools/36.0.0
$BT/zipalign -c -P 16 4 app-universal-release-unsigned.apk
$BT/apksigner sign --ks ~/.android/debug.keystore --ks-pass pass:android --key-pass pass:android \
  --ks-key-alias androiddebugkey --out BibliotecaMusical-teste.apk app-universal-release-unsigned.apk
$BT/apksigner verify --verbose BibliotecaMusical-teste.apk
```

**Esta assinatura não serve para loja.** Para publicar é preciso uma chave **própria**, criada e guardada pelo
responsável (quem perde a chave não consegue mais atualizar o app).

## Entregar em zip com o commit no nome

O APK é entregue **dentro de um `.zip` com o commit no nome**, para o responsável distinguir um build do outro:

```sh
C=$(git rev-parse --short=7 HEAD)   # o commit do build (árvore limpa), lido ANTES de sair da pasta do repositório
cd "<pasta de entrega dos zips>"   # a pasta de entrega dos zips do responsável (não é o repositório)
zip -j BibliotecaMusical-teste-$C.zip BibliotecaMusical-teste.apk
sha256sum BibliotecaMusical-teste-$C.zip
rm BibliotecaMusical-teste.apk BibliotecaMusical-teste.apk.idsig     # o apksigner deixa um .idsig ao lado
```

Os zips (e os pacotes de sons, `docs/pacote-de-sons.md`) vão **direto para a pasta de entrega**, a pedido do
responsável (antes iam para `~/Downloads`, e ele os movia para lá).

> **Nextcloud fora do ar (2026-11-23):** enquanto ele não volta, os zips vão para `~/Downloads/BibliotecaMusical/` (sem `archive/`: só se move o que o responsável mandar). Onde ficam depois é uma pendência ([`roadmap-pendencias.md`](roadmap-pendencias.md), seção 8).

**Arrumação da pasta (pedido do responsável, 2026-11-16; de 10 para 5 zips em 2026-11-22):** ficam **fora** só os **5 zips de APK mais recentes**; todo o resto
(zips de APK mais antigos e materiais soltos, como as comparações de bancos e as prévias de timbres) vai para a subpasta
**`archive/`**. Ao entregar um zip novo, o mais antigo que sobrar passa para `archive/` (só se move, nada se apaga). Um arquivo
de teste que acompanha o APK (por exemplo o pacote de partituras) fica ao lado dele e segue a mesma regra depois.

**O identificador do build é o commit** (7 caracteres, o mesmo de **Ajustes, "Sobre"**), e não mais um número em sequência (até o 071 era numerado; o 072 em diante já usa o commit). Por isso o build sai de uma **árvore limpa e já commitada**: com alterações locais o rótulo leva "+" e o zip não teria nome certo. **Acrescente a linha a cada build** (a primeira coluna é o commit). A versão e o
commit são os que aparecem em **Ajustes, "Sobre"** (`Versão X.Y.Z (commit)`).

### Roteiro das partituras (APK **020**)

Precisa de **internet** (o pacote vem do servidor). O hinário de teste (5 hinos) já vem no app, então o pré-requisito está cumprido.
1. Instale o **020** (`BibliotecaMusical-teste-020.zip`, extraia o `.apk`) e abra um hino. A aba **Partitura** aparece com o aviso e o botão
   **Abrir Ajustes**, que deve levar a Ajustes.
2. Em **Ajustes**, ache o card **Partituras**: "0,2 MB · Não instaladas" e o botão **Baixar (0,2 MB)**. Toque nele: aparece o progresso, depois
   "Conferindo o arquivo…" e "Instalando…", e o card passa a "Instaladas: 5 partituras" com o botão **Remover**. Se aparecer um erro, **anote o
   texto exato** (ele diz a etapa: rede, arquivo que não confere, ou o motivo de uma partitura recusada).
3. Abra os hinos 1, 276, 283, 398 e 457: a aba Partitura mostra a partitura. Conferir: **notas, letra e o andamento** ("♩ = 58", com a figura da
   nota) legíveis; as **bandeirolas** das colcheias na mesma cor das notas; o **zoom** (− / 100% / +) e **rolar para os lados** quando ampliada;
   trocar para o tema **escuro** e o **Alto contraste** em Ajustes.
4. Com a **fonte do sistema grande**, a aba continua utilizável? E com o celular **deitado** (barra de abas na lateral)?
5. **Remover** no card apaga só as partituras (o hinário fica): a aba volta ao aviso e o card a "Não instaladas".
6. **Importar hinário** só mostra arquivos `.json` agora.

**Histórico (018 e 019):** o 018 falhou ao importar o zip no Android ("a chamada não trouxe os bytes do arquivo": o Android não entrega corpo
binário ao Rust) e o 019 corrigiu isso mandando o zip em base64; o 020 troca esse fluxo pelo download automático, e o pacote combinado
(com `hinario.json`) **não funciona mais**.

## Instalar no celular

Copie o `.apk` para o aparelho e abra. O Android pede para permitir "instalar apps desconhecidos" daquela origem, e o
Play Protect pode avisar que o app não é conhecido (esperado num APK de teste).
